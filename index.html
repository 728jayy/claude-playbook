Claude 101

Plain-English summary

Claude is most useful when you treat it like a thinking partner, not just a search box. Your job is to bring context, judgment, and final responsibility.

Concrete example for non-tech readers

Ask Claude to compare two go-to-market options. Give it your company context, constraints, and success metrics. Then ask it to challenge its own recommendation before you use it.

Original course notes, revised for v1.1

This course is about using Claude not as a simple chatbot, but as a Thought Partner. An AI that combines with your own expertise to produce the best possible results.

Core Principles & Concepts

These are the foundational ideas behind how Claude works and what you need to know for effective AI collaboration.

  • Constitutional AI (a training approach for safer behavior): Claude is trained toward being helpful, harmless, and honest. This improves alignment, but it does not make Claude mistake-free. For important work, you still need human review and fact-checking.
  • Thought Partner: Claude is not a simple Q&A tool. It remembers your half-formed ideas and works as an active collaborator on complex thinking, strategic analysis, coding, and problem-solving.
  • Large Context Window and RAG (Retrieval-Augmented Generation - a method where the AI looks up relevant documents before answering): Claude can handle very large amounts of context, but the exact context window depends on the model. Some current Claude models support up to 1M tokens, while others support 200k. More context is not automatically better. For very large or external information, use retrieval/search/RAG, compaction, or careful chunking rather than assuming Claude will remember everything automatically.
  • The 4D Framework for AI Fluency: The four core skills for working effectively with AI.

Delegation - Strategically dividing work between humans and AI.

Description - Communicating clearly and giving precise instructions to the AI system.

Discernment - Critically evaluating the AI's output and reasoning process.

Diligence - Using AI responsibly and ethically, with transparency.

  • Extended Thinking: A hybrid reasoning mode where, instead of giving an instant answer, Claude works through complex analysis, math, or coding problems step by step.
  • 3-Step Prompt Engineering Framework (prompt = the instruction you give the AI): The key is to write naturally and clearly, like giving a task to a coworker. The formula is: Set the context -> Define the task -> Specify the rules.
  • Visual Creation with Artifacts: Artifacts are independent, interactive outputs that don't get buried in the chat window.

Supported formats: Markdown documents, code snippets (Python, JavaScript, etc.), full HTML web pages, SVG images (a type of vector graphic), Mermaid diagrams (a way to draw flowcharts from text), and React components (small pieces of interactive web pages).

Tip: Explicitly ask Claude to "create this as an artifact." The result can be previewed, viewed as code, downloaded, or published as a public link (and unpublished later).

Practical Implementation Guide

How to bring Claude into real work and avoid common mistakes.

Expanding the Ecosystem: Connectors and Enterprise Search

Through MCP (Model Context Protocol - a standard way to connect AI to outside tools and data), Claude can work with your real business data.

  • Web Connectors: Connect to cloud services like Google Drive, Notion, Slack, and Asana so you can search documents, summarize emails, and create tickets directly from the chat.
  • Desktop Extensions: Support local file system access, browser control, and integration with native applications (apps installed on your computer).
  • Enterprise Search: A dedicated feature that searches across multiple internal tools at once (SharePoint, Slack, Gmail, etc.) and gives a combined answer with citations (sources).

Research Mode for Deep Analysis

Beyond simple search, Research Mode is an autonomous research workflow where Claude can perform multi-step investigation, depending on product availability and permissions.

  • How it works: Plan the approach (Extended Thinking) -> Run multiple searches and follow leads -> Synthesize the information -> Generate a verifiable report with citations.
  • Time required: The course frames this as a longer-running workflow rather than instant chat. Timing can vary by product setup, prompt complexity, and data access. Treat the output as a research draft that still needs review.
  • Tip: Be very specific in the prompt about goals, structure, and constraints (budget, schedule, etc.).

Strategic Insights & Considerations

Strategies to avoid anti-patterns (common bad habits) and get the most value when bringing Claude into your work.

  • Build a Delegation-Diligence Loop: Blindly trusting AI analysis is dangerous. Use past data where you already know the right answer to systematically test Claude's analytical ability. Carefully evaluate the output for logical gaps (diligence), revise the prompt, and re-test. Only delegate work after trust has been built.
  • Adopt an Iterative Mindset: It's rare to get a perfect result from the first prompt. Treat the first draft as a starting point and refine it with specific feedback like, "Delete the first two paragraphs and rewrite the conclusion to be more action-oriented." If the conversation goes off track, it's more efficient to start a new chat.
  • Understand Security and Data Access: When using connectors and enterprise search, Claude can only access data that you yourself have permission to see. Conversations stay private, and connected data is not separately indexed or used for training. However, for sensitive actions in tools like the Chrome extension (such as making payments), human final approval is required.
  • Prevent Hallucinations and Fact-Check (hallucination = when AI makes up something that sounds true but is wrong): For high-stakes work, always ask for citations, turn on web search to ground answers in current information, and independently verify key facts.
  • Always Provide Human Context: Claude provides powerful intelligence, but the context and expertise that give the work meaning are the human's job. Don't outsource everything; communicate with Claude the way you would with a data analyst colleague - ask for the basis of answers and request a clear process.

Claude Code 101

Plain-English summary

Claude Code is an AI coding assistant that can inspect files, plan changes, edit code, and run commands with permission.

Concrete example for non-tech readers

A PM can ask Claude Code to explain where a payment bug may come from. Claude can search the codebase, propose a plan, and show which files matter, while the developer approves risky actions.

Term from the coursePlain-English translation

Pull Requesta proposed code change for review

Original course notes, revised for v1.1

This playbook is for developers. It covers Claude Code, an AI coding agent tool, from how it works to advanced custom settings. The goal is to master Claude not just as a code generator, but as an agent that solves problems by interacting with the environment on its own.

Core Principles & Concepts

The foundational concepts that make Claude Code different from chat-based AI like Claude.ai.

  • Agentic Coding Tool (agentic = able to act on its own): Beyond just returning text or code, Claude Code directly accesses your local file system, terminal (the text-based command window on your computer), and the entire codebase. To reach a goal, it interacts with the environment, modifies code, and runs commands autonomously.
  • The Agentic Loop: The heart of how Claude Code works. When you give it a prompt, it repeats this cycle in real time:

Gather Context - Search the codebase for the information it needs.

Take Action - Modify files or run terminal commands.

Verify Results - Check whether the work was done correctly. If not, run the loop again.

  • Context Window: Claude's working memory. Reading files, running commands, and conversation history all take up space. It's not infinite, so the agent doesn't load all your code - it strategically finds only what it needs.
  • Tools and Semantic Understanding (semantic = based on meaning, not just keywords): Claude has tools like Bash (terminal), file read/write, and web search. It decides on its own which tool to use and when, based on understanding the meaning of the task.
  • Permissions and Modes: Autonomy must come with control. The developer keeps control through these modes:

Approval Mode - Asks for explicit approval before modifying files or running commands (default).

Auto-accept - Auto-approves file edits, but still asks before running commands.

Plan Mode - Uses only read-only tools to plan the work, without making any actual changes.

Practical Implementation Guide

Concrete workflows and setup tips to maximize productivity.

The 4-Step Core Workflow: Explore -> Plan -> Code -> Commit

Instead of asking Claude to write code right away, follow this process to dramatically reduce trial and error.

  • Explore: Have Claude fully understand the project structure and style (for example, by using a subagent - a separate helper agent).
  • Plan: Press Shift + Tab to enter Plan Mode and build the implementation strategy. This is the most important step: review and Course-correct (adjust direction) the action plan Claude proposes before any code is written.
  • Code: Based on the approved plan, let Claude autonomously edit files and run terminal commands (like running the test suite). Always give clear success criteria.
  • Commit: Call the code-reviewer subagent for an unbiased code review, then use the /commit- push-pr skill to create a PR (Pull Request - a proposal to merge code changes into the main project) in one step.

Context (Memory) Optimization Commands

Performance drops when the context window is full. Manage memory with these commands:

  • /context: Visualize current context usage as a graph by category.
  • /compact: Summarize the long session so far down to the essentials, freeing up space (useful when continuing the same feature).
  • /clear: Erase all previous memory and start a completely new task (prevents bias from earlier conversations).

Project Customization

  • CLAUDE.md (Project Memory): An onboarding guide placed at the project root. Record your tech stack, run commands, and code style (e.g., "Use 2-space indentation"), and Claude will automatically read it every session. (You can auto-generate it with /init.)
  • Subagents: Run complex exploration or review tasks in parallel in a separate context window from the main agent. Only the final summary is passed to the main window, keeping the context clean.
  • Skills: Define a specific way of working (e.g., commit message format) in a Markdown file. Claude can load the skill when the request matches the skill description and permissions allow it. Clear descriptions make activation more reliable.
  • MCP (Model Context Protocol): An open standard for connecting Claude to external data sources or tools outside the codebase, such as Linear, AWS, or external databases.
  • Hooks: Forced rules that work deterministically (with a guaranteed result), not based on probability. Set in settings.json.

PostToolUse - Always run a code formatter like Prettier (a tool that auto-formats code) after a file edit.

PreToolUse - Detect and block destructive commands like rm -rf (a Linux command that deletes files permanently) or production database changes at the source.

Strategic Insights & Considerations

  • Strategic Value - Debug and Destress: The real value of Claude Code is not just typing faster. It's that you can delegate energy-draining tasks - complex bug hunting, repetitive refactoring, environment setup - to the AI agent, so you can focus on creative, essential work like architecture design and business logic.

Real-World Anti-patterns and Cautions

  • Vague Prompts (Context Bloat): Symptom - Short, vague instructions like "fix this." Result - Claude wastes the precious context window exploring many files just to figure out what you mean. Solution - Detailed, specific prompts actually save context.
  • Reckless Auto-approval (Bypassing Permissions): Symptom - Allowing all command execution for convenience. Result - A hallucination or misjudgment by the AI can cause critical system

changes or data deletion. Solution - Keep Approval Mode by default, or use a PreToolUse hook to block dangerous commands at the system level (return exit code 2 to block).

  • Neglected MCP Servers and Tools: Symptom - Leaving many MCP servers turned on that have nothing to do with your current project. Result - Every active tool's definition takes up context window space, leaving less room for actual code analysis. (Too many active tools can waste context and make tool selection harder. Keep only the tools that are relevant to the current task.) Solution - Use the /mcp command to immediately disable servers you aren't using.
  • Over-bloated CLAUDE.md: Symptom - Stuffing every project document and minor rule into CLAUDE.md. Result - A huge text block is added to the prompt every session, wasting context from the start. Solution - Start with no file at all, then selectively record only the things Claude often gets wrong. For large documents, use reference links like @README.md instead.

Introduction to Claude Cowork

Plain-English summary

Cowork is about delegation. Instead of asking one-off chat questions, you ask Claude to work across files and produce a real deliverable.

Give Claude a folder of interview notes and ask it to create a first-draft customer insights memo. You still review the logic and numbers before sharing it.

Original course notes, revised for v1.1

Core Principles & Concepts

Cowork is more than a chat-based AI. It is an action-oriented AI agent that reads and edits files directly in your local environment and produces final deliverables. It shifts the work paradigm from Conversation to Delegation.

The 3 Core Operating Principles (Plan, Execute, Connect)

  • Plan: Before doing a multi-step task, Claude proposes its approach and asks for your review and approval.
  • Execute: Carries out long-running tasks like file creation and data analysis autonomously, in an isolated environment on your local computer.
  • Connect: Integrates with your existing work tools - email, shared drives, Slack - and gathers context automatically, with no manual copy-pasting.

Extended Agentic Capabilities

  • Subagents: To handle several complex, independent tasks in parallel, Cowork runs separate agents at the same time (for example, comparing multiple suppliers simultaneously).
  • Local Computation: No need to upload or download files - the AI runs code and records results right where the files are.
  • Plugins & Skills: Domain-specific knowledge and workflows for fields like sales or finance are provided as packaged Skills, enabling expert-level approaches.
  • Native Artifacts Creation: Goes beyond text answers to produce real, finished files saved to your drive: PowerPoint with editable charts, Excel with working formulas, Word documents with tracked changes.

Practical Implementation Guide

The 4-Step Core Loop

Every Cowork task is completed through your instructions, the AI's plan, and Steering (interactive course- correction).

  • Describe: Clearly state what to review, the desired output, and where to save it. If information is missing, Claude asks follow-up questions.
  • Review & Answer: Check the work plan Claude proposes, choose priorities or approaches, and approve.
  • Execute & Steer: Watch the progress panel to see in real time which files Claude is reading and what it is producing. You can type into the chat at any time to change direction.
  • Open: Open the final file created in the designated folder or connected tool (e.g., Gmail, Drive) and review/edit it as a draft.

The High-Efficiency Prompt Pattern

A successful Cowork prompt always includes three elements: [Input] + [Transformation] + [Output]

  • Input: Specify the source material location (e.g., "the meeting notes and last year's report in this folder").
  • Transformation: State the specific work to do (e.g., "apply the brand guidelines skill and extract the key action items").
  • Output: Specify the final format and location (e.g., "and turn it into a summarized slide deck (PPTX)").

Maintaining Context and Setting Up Automation

  • Projects: Give Instructions to a specific local folder to keep context across sessions. Set the participant roles, file-saving rules, and output format preferences once, and you don't have to explain them again.
  • Scheduled Tasks: Set verified prompts or skills to run automatically on a schedule (hourly, daily, weekly). Example: "Every Monday at 9 AM, check the calendar and draft an email of weekly priorities."

Strategic Insights & Considerations

Strategic Value: Breaking Through Limits of Scale

The real value of Cowork is in research and analysis at scale that you can't fit in a single chat. It's optimized for reading many documents in parallel, cross-checking them, and surfacing patterns, contradictions, and outliers that you'd never catch reading them one by one. It performs best when you ask sharp questions like "What claims contradict each other across these documents?" - not just simple summaries.

Operational Cautions and Anti-patterns

  • Clearly Distinguish Chat vs. Cowork: If you don't need file access, external tool integration, or real file creation - for example, simple Q&A or brainstorming - use Chat mode. It uses far fewer resources.
  • Failure to Optimize Models: If you insist on the top-tier model (Opus) for everything, your usage allocation drops fast. Pick strategically by task complexity: Sonnet (default) for everyday work, and Haiku for light, fast tasks.
  • Reviewing Mindset (Beware of Blind Trust): AI output always sounds confident, regardless of how accurate it is. Before any final decision or external sharing, you must open the actual file and personally review the numbers and the logic.

Security and Permission Management

  • Cowork runs in an isolated environment that only accesses folders and tools you have explicitly given permission to.
  • Permanent file deletion is never autonomous - it requires gated deletion (your prior approval).
  • If you're handling sensitive data with regulatory requirements, check the audit logging and compliance policies of your plan beforehand.

This course shows how Claude Code actually works in a development environment: gather context, plan, act, and verify.

Concrete example for non-tech readers

A hook is like a security checkpoint. If Claude tries to read a secret file or run a destructive command, the hook can stop it before damage happens.

Term from the coursePlain-English translation
SDKtoolkit developers use to add Claude to software
GitHub Actionsautomation inside GitHub

Original course notes, revised for v1.1

Core Principles & Concepts

Claude Code is more than a code generator - it's an intelligent partner that interacts directly with your development environment to autonomously solve complex problems.

  • 3-Stage Architecture of the Coding Assistant: To solve a task, it iterates through these intelligent stages: Gather Context -> Formulate a Plan -> Take an Action.
  • Tool Use Mechanism: The core idea that overcomes the limits of language models. The model issues commands as text, the system interprets them, and then performs file system control (Read, Write, Edit), system control (Bash, LS), and advanced functions (Agent, WebSearch).
  • Multi-layered Context Management: Unnecessary information hurts AI performance. Claude Code controls context through CLAUDE.md files at three levels:

CLAUDE.md (Project Level) - Common guidelines committed to Git (a system that tracks code changes) and shared with the team.

CLAUDE.local.md (Local Level) - Personal settings and instructions.

~/.claude/CLAUDE.md (Global Level) - General-purpose guidelines that apply to all projects.

  • Extensibility and MCP: Through MCP (Model Context Protocol) servers, you can add tools that aren't built in (for example, browser control via Playwright - a browser automation tool) and expand capabilities almost without limit.
  • Control and Automation (Hooks & SDK - SDK = Software Development Kit, a set of tools to integrate Claude into your own software): Use PreToolUse and PostToolUse hooks to block AI behavior in advance or automate follow-up tasks. Use the SDK to integrate the AI into pipelines programmatically.

Key idea: Claude's strong tool-use ability is the foundation for solving complex, changing development tasks effectively while keeping security tight (no need to externally index your entire codebase).

Practical Implementation Guide

1. Initial Setup and Context Optimization

  • Project Initialization: Run /init in the terminal. It scans the entire codebase and auto-generates a CLAUDE.md that summarizes architecture and coding patterns. (Auto-approve file creation: Shift + Tab.)
  • Precise Context Injection:

@filename - Mention a specific file in a question to immediately include it in the context (e.g., "How does auth work? @auth.ts").

# command (memory mode) - In conversation, type something like # Use comments sparingly, and the rule will be intelligently merged into CLAUDE.md.

2. Conversation Control and Reasoning Modes

Core Principles & Concepts

This course defines AI not as a simple tech tool, but as a thinking partner that combines with human expertise to produce the best possible outcomes. It presents a fundamental collaboration framework that holds up even as the technology changes rapidly.

3 Stages of AI Interaction Evolution

  • Automation: The AI runs a specific task with a clear, defined output, following the user's instructions (e.g., summarizing documents, drafting emails).
  • Augmentation: For complex problems with no single right answer, treat the AI as a creative thinking partner that explores and experiments with you.
  • Agency: An advanced stage where the user sets the knowledge boundaries and the vision instead of specific actions, and the AI carries out work on the user's behalf.

The 4D Framework for Human-AI Collaboration

The four core skills for effective and ethical interaction - independent of any specific tool or trendy prompt.

  • Delegation: Designing the structure - strategically splitting which parts need human expertise and which need AI efficiency.
  • Description: Communication - going beyond simple commands to provide rich context and convey your vision and intent precisely.
  • Discernment: Verification - critically reviewing the AI's outputs, logic, and process, and judging their value.
  • Diligence: Ethics - protecting data privacy, controlling bias, maintaining transparency in AI use, and taking responsibility for the final result.

Technical Nature of Generative AI

  • Non-retrieval Generation: Doesn't search a database for information. It generates new text based on statistical patterns it learned from massive amounts of data.
  • 2 Stages of Training: Pre-training (building a map of language from billions of pieces of text) and Fine-tuning (correcting it to follow instructions and avoid harm).
  • Context Window: The AI's working memory - the maximum amount of information it can process and remember at once.

Practical Implementation Guide

Step-by-step guidance and prompt engineering techniques to apply the 4D Framework right away.

Step 1: Strategic Delegation

  • Problem Awareness: Before the AI gets involved, clearly define the goal and success criteria using human expertise.
  • Platform Awareness: Understand the strengths of the AI model you'll use (speed, creativity, accuracy) and place it where it fits.
  • Task Distribution: Critical analysis and final decisions go to the human; large research and first drafts go to the AI.

Step 2: Multi-dimensional Description and Prompting AI cannot read minds. Always include these three dimensions (3P) in the prompt:

  • Product: Format, target audience, tone of the final output.
  • Process: The approach, analysis style, and step-by-step instructions the AI should use.
  • Performance: Set the interaction style (e.g., "Critically challenge my hypothesis," "Explore multiple possibilities").

6 Prompting Techniques for Professionals

  • Give Context: Provide background - who you are, why you need this information, and where it will be used.
  • Show Examples: Provide examples of the output style or format you want, so the AI can imitate the pattern (Few-shot prompting).
  • Specify Constraints: Clearly state answer length, words to avoid, and required formats (Markdown, JSON, etc.).
  • Break into Steps: Lay out the order for complex tasks to prevent logical errors. Ask for a visible plan, assumptions, checks, and final rationale that you can evaluate.
  • Ask to Think First: Before producing the answer, give the AI thinking space to review the factors and constraints.
  • Define Role: Assign a persona like "As a UX professional with 10 years of experience…" to invite a more expert perspective.

Step 3: The Description-Discernment Loop

  • Product Discernment: Is the output factually accurate? Does it actually solve the problem?
  • Process Discernment: Are there logical leaps or circular reasoning in the AI's thinking?
  • Iteration: Based on what discernment finds, revise the prompt and run the feedback loop until the result is good. When you're stuck, opening a new chat window helps.

Strategic Insights & Considerations

Strategic perspectives that leaders and practitioners must internalize to maximize AI value and minimize risk.

3 Principles for Responsible AI Use (Diligence)

  • Creation Diligence: Before entering sensitive data, critically check the AI system's data protection policy and your organization's security rules.
  • Transparency Diligence: Honestly disclose to colleagues and stakeholders what the AI contributed to the work, building a trust-based collaboration.
  • Deployment Diligence: Personally verify the AI's output for accuracy, bias, and copyright. Final responsibility rests entirely with the human.

Critical Anti-patterns and Cautions

  • Blind Trust in Hallucinations: AI can deliver wrong information in a very confident tone. Cross- checking based on human domain expertise is essential.
  • Ignoring Knowledge Cutoff: The model doesn't know information from after a certain training date. Recognize this and combine with external search tools (like RAG) when needed.
  • Over-injecting Context: If the context window limit is exceeded, the AI may forget the early parts of the conversation or key instructions. Keep things concise and focused.
  • Ignoring Non-deterministic Behavior: The same prompt can produce different results each time. For tasks where consistency is critical (strict code generation, compliance documents), thorough human supervision is required.
  • The "Silver Bullet" Illusion: AI is not magic that solves everything. Reckless delegation without domain knowledge causes a project to lose its direction.

Core Principles & Concepts

This course covers the foundational architecture and engineering principles for integrating the Claude API (a way for software developers to use Claude inside their own applications) into reliable, enterprise-grade AI systems - not just as a text generator.

  • Stateless Conversations and Message Lifecycle (stateless = doesn't remember anything between requests): The Claude API does not remember previous conversation context. To build multi-turn conversations, the developer must manage the message array (history) of User and Assistant messages and send the entire context with each request.
  • Prompt Engineering and Evaluation Pipeline: Don't rely on intuition when writing prompts. Control quality with clear instructions, structure via XML tags (a way to wrap text in labels like <example>...</example> so the AI knows what each part is), and multi-shot examples. More importantly, follow the rule "You can't improve what you can't measure" - build a test dataset and use a Model Grader (an AI that scores another AI's output) to produce objective scores in an iterative evaluation pipeline.
  • Tool Use and the Model Context Protocol (MCP): Connect external functions (Tools) to overcome the limits of Claude's training data. MCP separates these tools, resources, and prompts into a standardized server-client structure. Developers can give Claude access to external systems (GitHub, databases, etc.) without writing complex integration code every time.
  • Retrieval-Augmented Generation (RAG) and Hybrid Search: To handle large documents, split text into logical Chunks (small pieces) and create embeddings (numerical representations of text that capture meaning). To make up for the weakness of Semantic Search (search by meaning) on things like proper nouns and ID numbers, combine it with BM25 (a Lexical Search method that matches exact keywords) in a multi-index Hybrid Search architecture.
  • Workflows vs. Agents: Choose the architecture by the nature of the problem. For tasks with clear steps, design Workflows (parallelization, chaining, routing) to maximize reliability and predictability. For unpredictable, variable tasks, give the model abstract tools and let it plan on its own - the Agent pattern.

Practical Implementation Guide

Concrete patterns and checklists to maximize Claude API performance and efficiency.

1. Reliably Extracting Structured Data (JSON)

In automation pipelines that need pure JSON or code with no commentary, combine Assistant Message Prefilling (giving the AI the start of its answer) with Stop Sequences (telling the AI where to stop). Conceptual example: pre-fill the assistant message with "```json" so the model is forced to start in markdown JSON format, and set stop_sequences=["```"] so generation stops the moment the closing markdown tag appears. The result is clean JSON with no extra text.

2. Implementing the Multi-turn Tool Use Loop

When Claude requests a tool, you must build an automated conversation loop that handles it and returns a result.

  • Detect: Check whether stop_reason in the response is "tool_use".
  • Execute: Extract the function name and arguments (input) from the tool_use block in response.content, then run the local function.
  • Return Result: Wrap the execution result in a tool_result block and send it back to Claude as a User message. (The tool_use_id must match.)

3. Optimizing Cost and Latency with Prompt Caching

When you repeatedly send a large system prompt, long document, or complex tool schema, apply prompt caching to improve cost and speed. The current public docs describe 5-minute and 1-hour cache options, with model-dependent minimum lengths and pricing.

  • Set a cache breakpoint by adding the {"cache_control": {"type": "ephemeral"}} property to the last item of the system prompt or tool array.
  • Caution: If even a single character before the cache breakpoint changes, the cache becomes invalid. So put static content (documents, schemas) at the front.

4. RAG Pipeline Optimization Checklist

  • Chunking Strategy: If the structure is clear (like Markdown), use header-based splitting. For plain text, use sentence-based splitting with Overlap (small repeated content between chunks) to prevent context loss.
  • Store Original Text: In your vector database, store not only the embedding numbers but also the original text content that will be injected into the prompt after search.
  • Reciprocal Rank Fusion (RRF): When merging results from vector search (meaning) and BM25 (keywords), apply the RRF formula to surface the most relevant chunks.
  • Strategic Tuning of the Temperature Parameter (temperature = how random the AI's output is): Don't use the default for everything. Use lower temperature for data extraction, code generation, and fact-based answers; use higher temperature for brainstorming or creative writing. Exact values should be tested for your use case. Temperature affects variability and creativity. Lower temperature can improve consistency, but it does not guarantee factual accuracy. Use grounding, citations, and evaluation tests for factual reliability.

Strategic Insights & Considerations

Architectural trade-offs and anti-patterns to know when launching a successful AI product.

  • The Long Prompt Problem: If you cram many constraints into one prompt (e.g., "don't reveal you're an AI," "no emojis," "professional tone"), the model will miss some of them. To fix this, use Chaining (generate a draft, then issue a revision instruction) or Routing (first classify the request type, then send it to a specialized prompt).
  • Missing Environment Inspection in Agents (Critical Anti-pattern): When you give an agent the power to edit files or operate a UI, you must also give it tools to observe the result. Without those, it's like an agent working blind. Explicitly require feedback loops in the system prompt: read the file before changing it, take a screenshot after manipulating the UI.
  • UX Delays in Streaming and Tool Calls: When calling tools, the API buffers chunks until a full JSON key-value pair is complete, which can delay the UI. If you need an instant response, you can set fine_grained=True to skip this validation, but then you must implement client-side error handling for incomplete JSON.
  • Beware Agent Maximalism (Workflows > Agents): Agents are flexible, but their predictability and success rate are relatively low. Production users want a product that consistently works, not a flashy agent. Apply highly reliable workflow patterns (like evaluator-optimizer) wherever possible, and reserve agents for genuinely dynamic areas that can't be defined ahead of time.

Core Principles & Concepts

Model Context Protocol (MCP) is a standard communication layer designed so large language models (LLMs) can interact with external data and tools. It reduces the burden of writing complex integration code and gracefully provides the model with the context it needs.

1. Architectural Separation and Burden Shift

  • Limitation of the Old Way: Developers had to define, test, and maintain tool schemas (definitions) and functions for each API endpoint, which was very expensive.
  • MCP Architecture: Splits the system into Client and Server. The burden of defining and executing tools moves to a specialized MCP Server. Developers just plug into a server that's already defined.
  • Transport Agnostic: Not tied to any one protocol. Use Standard IO (a way for two programs on the same computer to talk) for local environments, and HTTP, Webhooks, or Websockets for remote environments.

2. The 3 Core Primitives of an MCP Server

An MCP server acts as a wrapper between an external service (like GitHub or Google Drive) and the LLM. It provides three things:

  • Tools (Model-controlled): Executable functional interfaces that the model itself decides to call as needed (e.g., editing a file, calling an API).
  • Resources (App-controlled): Read-only channels through which the server shares its data or documents with the client. Used for context injection.
  • Prompts (User-controlled): High-quality instruction templates pre-tuned and stored on the server, so the model performs specific tasks better.

3. Full Communication Flow (Request-Response)

  • Tool Discovery: The client sends a ListToolsRequest to the server to get a list of available tools.
  • Pass to Model: The user's question and the tool list are sent to Claude.
  • Decision and Request: When Claude decides to use a tool, the client sends a CallToolRequest to the server.
  • Return Result: The server calls the external API and returns a CallToolResult, and Claude uses it to produce the final answer.

Practical Implementation Guide

With the official Python MCP SDK, you can build powerful servers and clients with just Python decorators and type hints - no need to manually write complex JSON schemas.

1. Building an MCP Server

  • Initialization: Use from mcp.server.fastmcp import FastMCP and initialize the server in a single line.
  • Defining Tools (@mcp.tool): Add the decorator above a function to register it as a tool. Using pydantic's Field and Python type hints, the SDK auto-generates a JSON schema that Claude understands.
  • Defining Resources (@mcp.resource):

Direct Resource - Fixed URI (e.g., "docs://documents"). Used for returning lists with no arguments.

Templated Resource - Includes dynamic parameters (e.g., "docs://documents/{doc_id}"). The SDK auto-extracts arguments from the URI and passes them to the function.

Always specify mime_type (e.g., application/json, text/plain) so clients parse data correctly.

  • Defining Prompts (@mcp.prompt): Take user input variables (e.g., doc_id) and return a completed message list (list[base.Message]).

2. Building an MCP Client

  • Session Management: Use stdio_client and ClientSession. In async environments, use AsyncExitStack to safely manage connections and prevent resource leaks.
  • Key methods:

list_tools() / call_tool(name, args) - list and run tools.

read_resource(uri) - check the mimeType of the returned ReadResourceResult and parse JSON (json.loads) or treat as text accordingly.

list_prompts() / get_prompt(name, args) - list prompts and receive the final message with variables filled in.

3. Testing and Debugging (MCP Server Inspector)

A built-in browser-based tool that lets you verify server logic on its own without running the whole app.

  • Run command: mcp dev mcp_server.py
  • Use: Open the web UI and move between Resources, Prompts, and Tools tabs. Enter arguments directly and view returned JSON/text in real time. (Example: run a document-edit tool, then use a read tool to verify that the change persisted.)

Strategic Insights & Considerations

Whether your project succeeds depends on understanding the architecture's intent and choosing the right primitive (Tools, Resources, Prompts) for the job.

1. Strategic Guidelines for Choosing Primitives

  • Tools - When granting autonomy to the model: Use tools when the model needs to actively act based on the situation: calculations, external API calls, file edits.
  • Resources - When injecting app context: Use resources to populate UI autocomplete lists, or to immediately push data into the model's prompt when a user mentions a specific document (@doc) - without the overhead of a tool call.
  • Prompts - When standardizing user workflows: Don't make users type complex instructions every time. Define a polished, domain-aware prompt on the server, and let users get consistent, high-quality results from a slash command (/format) or a button click.

2. Cautions for Real-World Use (Anti-patterns & Details)

  • Avoid Manual JSON Schema Writing: Don't write huge JSON by hand to describe tools to the model, like in old API integrations. Use the Python SDK's decorators and the description attribute of pydantic.Field to automate type validation and schema generation. Maintainability shoots up.
  • Don't Skip MIME Type Handling: If the client ignores the mime_type the server sends and treats everything as text, you lose the benefits of structured data (like JSON). Always implement MIME- type-based parsing on the client.
  • Confusing Tools and Resources: If you only need to read data and inject it into the prompt, use Resources, not Tools. Using Tools adds an extra step where the model decides whether to call them, which adds latency.
  • Misunderstanding Building Both Client and Server: This course implements both for learning. In real production, you typically build only the MCP server and connect to a strong existing client (like Claude Desktop), or build only a client for your own app and use public MCP servers.

Core Principles & Concepts

Four core principles that run through MCP's advanced features and the server-client architecture.

Sampling: Shifting Responsibility and Cost

  • Instead of the server connecting directly to an LLM (like Claude), the server delegates text generation to the connected client.
  • This lowers the server's structural complexity, and it fully shifts API key management and token cost burden to the client (user) side.

Roots: Context-based Safe File Navigation

  • A permission system that explicitly defines the boundaries of the local file system the server can access.
  • Even if the AI doesn't know the exact full path of a file, it can autonomously discover files within the allowed roots - maximizing UX.

Bidirectional JSON Messages

  • Follows the JSON-RPC 2.0 standard (a common rule for how programs send messages to each other in JSON format), made up of Request-Result pairs (which expect a reply) and Notifications (one-way status reports).
  • The most important feature: not only the client but also the server can initiate requests (Server- initiated Requests). Examples: sampling requests, root-list requests.

Transport Mechanisms: STDIO vs StreamableHTTP

  • STDIO: A local-optimized method where the client runs the server as a child process and communicates via standard input/output (stdin/stdout).
  • StreamableHTTP: A method for remote hosting. To overcome HTTP's one-way limit, it uses SSE (Server-Sent Events - a way for a server to push messages to a client over HTTP) so the server can push messages to the client.

Practical Implementation Guide

A. Implementing Notifications for Better UX

  • Purpose: Remove user uncertainty during long-running tasks like large data research (so they don't think the system is frozen).
  • Server-side (using the Context object):

Send a log: await context.info("Research in progress…")

Send a progress update: await context.report_progress(current, total)

  • Client-side: Pass logging_callback and progress_callback functions when creating a ClientSession or calling a tool, and reflect them in the UI (terminal, progress bar, etc.).

B. Applying the Sampling Workflow

  • Server side (Request): Inside a tool function, call ctx.session.create_message to define the prompt, max tokens, and system prompt, and send it to the client.
  • Client side (Execute): Write a sampling_callback function that hands the server's message to a real LLM (e.g., Anthropic SDK) and returns the generated result to the server as a CreateMessageResult.

C. Roots-based File Access Control Checklist

  • Add list_roots and read_dir tools to the server so the AI can navigate directories.
  • [Required] Implement a helper function like is_path_allowed() in your server code yourself. Verify that the requested path is within the approved roots before doing any file work.

D. Transport Configuration (FastMCP-based)

  • Local environment (STDIO): mcp.run(transport="stdio")

Caution: Strictly forbid regular print() statements in server code. Since stdout is the communication channel, the protocol breaks. Always use MCP logging notifications.

  • Remote environment (HTTP): mcp.run(transport="streamable-http")

Works over a multi-connection pattern: Initialization (POST) -> SSE connection (GET) -> tool calls (POST).

Strategic Insights & Considerations

Architectural limits and security anti-patterns you may hit when deploying to production.

Critical Trade-offs Between Scaling and Features

  • Issue: When you add a load balancer (a system that splits traffic across many servers) to handle many users, the client's POST requests can be routed to a different server instance that doesn't have the SSE connection, breaking communication.
  • Solution: Set the stateless_http=True flag to switch to stateless mode.
  • Caution (loss of features): When stateless mode is on, the SSE workaround is disabled. As a result, server-initiated requests, sampling, progress reports, and resource subscriptions all become impossible. Only suitable for simple tool-call servers.

Misunderstanding Security Responsibility (Anti-pattern)

  • Risk: Believing that the MCP SDK will automatically block access outside the paths in Roots is a serious security vulnerability.
  • Insight: Roots only provides navigation context to the AI. Physical access control is entirely the server developer's job. Path-validation logic before every file I/O is mandatory.

Public Server Design Economics

  • If you build a public MCP server anyone can access, having the server manage the LLM API key directly is an anti-pattern that leads to a cost bomb.
  • You must adopt a Sampling architecture to separate the complexity of AI integration and the responsibility for token charges to the client side, which already has the credentials.

Understanding the JSON Response Flag

  • Setting json_response=True disables streaming responses and returns only the final result as pure JSON. Useful for simple integration systems that don't need intermediate progress messages or logs.

Core Principles & Concepts

A macro, strategic decision process: shifting from "How do I use AI?" to "How do I make the best decisions about AI?"

  • Two-way interaction: Delegation decisions immediately raise ethical questions (diligence), and ethical constraints (diligence) reshape how you delegate work.
  • Components: Problem/platform recognition and task delegation (Delegation) ↔ responsibility for creation, transparency, and deployment (Diligence).
  • Effect: Ethical boundaries don't constrain - they catalyze more creative and powerful decisions.

(3) The Description-Discernment Loop

Beyond simple Input-Output, this is the micro, tactical process of building a Cognitive Environment where you and the AI think together.

  • 3 Core Lenses (The Three Ps):

Product - Start from a vague idea and refine the standards for the final output through iteration.

Process - Develop a shared approach to thinking and problem-solving.

Performance - Adjust the role and dynamic between you and the AI so you can do your best thinking.

Practical Implementation Guide

Concrete methods for effectively teaching the 4D framework to students and assessing their learning.

(1) 4 Teaching Approaches

  • Linear: Best for beginners. Sequential learning: Delegation -> Description -> Discernment -> Diligence.
  • Non-linear (autonomous start): For experienced learners. Understand AI work as an organic system and start flexibly from whichever skill the situation demands.
  • Focused: Drill deeply into one skill (e.g., discernment) within limited time, maximizing mastery.
  • Two Loops: Advanced approach. Split interactions into a strategic space (Delegation-Diligence) and a tactical space (Description-Discernment) to understand them systemically.

(2) 3-Dimensional Assessment Strategies

Don't measure "Did the student use AI?" but "How intelligently and responsibly did they collaborate?" - a multi-angle assessment framework.

  • Outcome-based: Evaluate the quality of the final product. (e.g., How impressively did they improve the AI output? Did they compare and analyze results across multiple AI platforms?)
  • Process-based: Evaluate how they collaborated over time. (e.g., Submit annotated chat logs, analyze pivots after failed attempts, record and narrate live work sessions.)
  • Reflection-based: Evaluate metacognitive (thinking about thinking) ability. (e.g., Keep a learning journal, explain why a strategy worked, write a personal policy statement on an ethical dilemma faced.)

(3) 3 Principles for Designing AI Fluency Assignments

  • Authenticity: Not artificial drills - handle real, current problems where AI partnership genuinely adds value.
  • Iteration: Beyond single-prompt entry - assignments must include the chance to revise, reconsider, and try again.
  • Pedagogy Transparency: Clearly tell students that the quality of the collaboration process and reflection itself - not just the final product - is the main thing being assessed.

  • Making Tacit Knowledge Explicit: If you can't clearly define what "quality" means in your field or how experts in it communicate (build Rubrics - scoring guides), you can't be a partner to AI.

  • Pedagogy: Use AI as a personalized tutor or simulation tool - but cultivate the wisdom to tell a learning system from a mere shortcut.

AI doesn't replace a nonprofit's mission - it's a strategic augmentation tool that helps

humans focus on more human values."

Non-tech takeaway

AI can help with scarce resources, but human mission judgment comes first.

Introduction to Agent Skills

Plain-English summary

Skills are reusable instruction packages. They help Claude apply a repeatable process without you rewriting the same prompt every time.

Concrete example for non-tech readers

A team creates a PRD-review skill that always checks user problem, success metrics, risk, and launch plan.

Term from the coursePlain-English translation
SKILL.mdthe instruction file for a skill
Frontmattersettings at the top of a markdown file
Triggerthe type of request that makes a skill activate

Original course notes, revised for v1.1

Skills in Claude Code is the core feature that removes repetitive instructions and automates work by teaching Claude specific expertise just once. Below are the foundational concepts and how it works.

Core Principles & Concepts

On-demand Knowledge via Semantic Matching

  • A skill is a Markdown file (SKILL.md) that defines how to do a specific task.
  • Unlike settings that are always loaded, a skill activates only when the user's request semantically matches the skill's description (matches by meaning).
  • This avoids loading unnecessary information and keeps the context window extremely efficient.

Scope and Distribution

  • Personal: Stored at ~/.claude/skills. Manages preferences (e.g., commit message style) shared across all your projects.
  • Project: Stored at ./.claude/skills in the repository root. Versioned with Git, automatically shared with all teammates who clone the repository (e.g., brand guidelines, code review standards).

Progressive Disclosure

  • For context optimization, it's recommended to keep the main SKILL.md file under 500 lines.
  • Detailed architecture guides or runnable scripts go into subdirectories like /references, /scripts, /assets - a multi-file structure where Claude reads only the linked piece when needed.

Priority Hierarchy

  • If skills with the same name conflict, the system applies just one based on a strict priority order.
  • Order: Enterprise (admin-enforced - highest) > Personal > Project > Plugins (lowest).

Practical Implementation Guide

1. Skill Creation and Testing Workflow

  • Create the directory: Make a folder with the same name as the skill. (e.g., mkdir -p ~/.claude/skills/pr-description)
  • Write SKILL.md: Create SKILL.md inside the folder with Frontmatter (metadata at the top of the file) and Instructions.
  • Restart the session: Skills load when Claude Code starts, so always restart the session.
  • Verify: Check loading with the command What skills are available?

2. Advanced Frontmatter Configuration (prompt example)

--- name: codebase-onboarding

description: Helps new developers understand how the system works. Use it when someone asks "Explain the architecture" or "How does this module work?" allowed-tools: Read, Grep, Glob, Bash model: sonnet --- # Instructions 1. When you get a question about system architecture, first read references/architecture-guide.md. 2. Don't modify code - provide explanations only.

  • description: Clearly state "what it does" and "when to use it," and include realistic trigger phrases users would actually type. This raises matching probability.
  • allowed-tools: Limit Claude's permissions for security-sensitive work. The example above blocks file edits and writes - a safe Read-only skill.

3. Best-fit Checklist for Each Claude Code Feature

Don't make everything a skill. Pick the right tool for the purpose.

  • Skills: Specialized knowledge needed only for certain tasks (e.g., a PR review checklist, debugging a specific framework). Loaded only on request.
  • CLAUDE.md: Project-wide standards and constraints that must always apply (e.g., "Never modify the database schema," "Always use TypeScript strict mode").
  • Hooks: Tasks that auto-run on a specific event, like file save or pre-tool-use validation.
  • Subagents: Use when delegating work in an isolated context separate from the main conversation.

4. Skill Integration with Subagents

  • Caution: Subagents do NOT automatically inherit skills from the main conversation.
  • Solution: Explicitly declare skills in the Frontmatter of your custom agent file in .claude/agents/. (skills: accessibility-audit, performance-check)

Strategic Insights & Considerations

  • Real Value and Distribution Strategy: The real value of skills is beyond personal convenience - it's organizational standardization. Asset-ize your team's IaC (Infrastructure as Code - managing cloud setup with code) writing standards, security policies, and brand guidelines as skills.

Git Sharing: Commit project-specific workflows to the repository to sync immediately with the team.

Enterprise Distribution: Mandatory security requirements or compliance can be deployed organization-wide via managed-settings.json by an admin, overriding personal settings to enforce a standard.

Script Bundling: For environment validation or data conversion, embedding tested utility scripts inside the skill - and using only the result as tokens - is overwhelmingly better than relying on AI-generated code, both for reliability and cost.

Anti-patterns and Troubleshooting Guide

What to check when a skill doesn't work as expected.

  • Trigger Failure (exists but doesn't run):

Cause: Semantic match failure between user request and description.

Fix: Add multiple realistic Trigger phrases users might say to the description.

  • Load Failure (not in the list):

Cause: Structural error.

Fix: Check that the file is named exactly SKILL.md (uppercase) and is in its own folder. Validate syntax with skills-ref validate [path], and trace loading errors with claude --debug.

  • Conflict and Shadowing (the wrong skill runs):

Cause: The skill name is too generic (e.g., review), or a higher-priority entry (Enterprise) has the same name.

Fix: Rename to something specific and distinct, like frontend-pr-review.

  • Runtime Errors (stops mid-execution):

Fix: Check execute permission on script files (chmod +x), and use forward slashes (/) as path separators on all paths, even on Windows. Note any external package dependencies in the description.

Master one-liner

If you find yourself giving Claude the same instruction over and over, that's the perfect

moment to turn it into a skill and sync it as an organizational asset."

Non-tech takeaway

If you repeat an instruction often, consider turning it into a skill.

One subagent researches competitors, another reviews technical risks, and the main agent synthesizes the final product recommendation.

Original course notes, revised for v1.1

This playbook gives strategic guidance for using the Subagents feature in Claude Code to split complex tasks and efficiently manage the context window.

Core Principles & Concepts

Subagents are specialized helper agents that Claude Code can delegate specific tasks to. The core mechanism: instead of solving a complex problem in one shot, break it into small, focused units.

  • Isolated Context: Each subagent runs in its own conversation context window, completely separated from the main conversation. Reading dozens of files, searches, tool calls - all that intermediate work doesn't pollute the main thread.
  • Token Efficiency and Better Focus: When the work is done, the subagent throws away the detailed log and returns only a summarized result to the main thread. This preserves space in the main context window and prevents Claude from losing earlier conversation context.
  • Autonomy with Custom Instructions: Through a system prompt you define, a subagent gets a specific role (e.g., code reviewer, doc generator) and uses its assigned tools to do the work autonomously.
  • Built-in Subagents: Claude Code includes three ready-to-use defaults.

General-purpose (Sonnet): For multi-purpose tasks needing both exploration and execution.

Explore (Haiku): For fast searches and structure exploration of a codebase.

Plan (Haiku/Sonnet): For research and analysis to plan before code changes.

Practical Implementation Guide

How to create and configure subagents so they don't wander and produce accurate results.

1. Subagent Creation Workflow

  • Invoke command: Type /agents in the chat to open the management interface.
  • Set scope: Choose between current-project (Project-level) and shared across all projects (User- level).
  • Auto-generation recommended: Rather than writing manually, describe the role you want to Claude (e.g., "an agent that reviews code for quality and security") and have it auto-generate the name, description, and prompt.

2. YAML Configuration File Optimization

The generated agent is saved as a .md file. The YAML data at the top is the key signal the main agent uses to decide "when and how to delegate."

  • Description: The criterion the main agent uses to call the subagent - and it sets the direction of the input prompt.

Proactively: Including the word "proactively" in the description makes Claude delegate work itself in suitable situations.

Specificity: Adding concrete instructions to the description like "specify exactly which files to review" makes the main agent write a much clearer input prompt to pass along.

  • Model: Choose the intelligence level by task type. (Fast tasks: Haiku, balanced: Sonnet, complex analysis: Opus)

3. The 3 Principles of System Prompt Design

The quality of the system prompt (the markdown body) determines the subagent's performance.

  • Define a Structured Output Format (the most important): Force a table of contents for the result, giving the subagent clear stopping points. This prevents infinite loops and runaway resource use.

1. Summary (overall evaluation)

2. Critical Issues (serious problems to fix immediately)

3. Major/Minor Issues (quality, style, etc.)

4. Recommendations

5. Approval Status

  • Require Reporting Obstacles: Tell the subagent to include any solutions it found during the work (dependency fixes, special flags, etc.) in the output. This saves the main thread time and tokens of re-analyzing the same problem.
  • Minimize Tool Permissions (Principle of Least Privilege): Grant only the tools needed for the task to prevent side effects.

Investigation/exploration: Read, Glob, Grep (read-only)

Code review: Add Bash (for git diff checks - git diff shows what code changed; no edit permission)

Code modification: Grant Edit, Write permission

Strategic Insights & Considerations

The key question for whether to use a subagent: "Does the intermediate work need to be visible in the main chat?" If you only need the result, delegate. If you need feedback on the process, stay in the main thread.

1. When Subagents Shine (Recommended Patterns)

  • Research & Investigation: When you need to find specific logic (like an authentication method) in an unfamiliar codebase. Hide the process of digging through dozens of files and get a clean result like "Authentication is in file X at line Y."
  • Specialized Code Review: The main agent loses objectivity about its own code. A subagent can review with fresh eyes (no writing history) and apply your team's specific review standards consistently.
  • Tasks with Custom Instructions: Very effective when you need special rules different from a base coding prompt - marketing copywriting (with a specific tone), design system compliance (using predefined CSS variables), etc.

2. Anti-patterns That Hurt Productivity

  • Expert Claims: Just writing "You are a Python expert" in the system prompt is meaningless. The Claude model already has that knowledge, and without specific tool usage or special instructions, there's no real difference from the main agent.
  • Sequential Pipelines: Delegating tasks like "reproduce the bug -> debug -> fix" - where each step depends on the previous step's findings - to a chain of agents is risky. Important context can get lost in handoffs between agents.
  • Test Runners: An agent that just summarizes test results as "pass/fail" hurts debugging. To solve a problem, you need full logs and context, so it's better to run tests directly on the main thread and check the full output.
Master one-liner

The essence of using subagents well is the isolation of context - Claude's token

efficiency and accuracy peak when you remove the noise of the middle steps and focus only on the final result."

Non-tech takeaway

Use subagents to reduce noise, not to create unnecessary handoffs.

Update (May 2026): Multi-agent orchestration is now in public beta

At Anthropic's developer event in May 2026 (Code with Claude), Anthropic moved a feature called multi-agent orchestration from an early test stage into public beta. In plain terms, this is the same idea as the subagents course you just read - one lead AI splits a big task into smaller pieces and hands each piece to a specialist - but Anthropic now offers it as a managed service that companies can use in production, not just inside Claude Code.

A useful real-world analogy: imagine a consulting engagement manager who breaks a client project into market research, financial modeling, and a final deck, then hands each piece to a specialist on the team. Each specialist works in their own workspace without crowding the engagement manager's desk, and the manager only sees the finished summary from each one. Multi-agent orchestration applies the same pattern to AI: each subagent gets its own model, instructions, tools, and separate working memory, and every step is logged in the Claude Console so a developer can trace who did what and why.

The takeaway from this course still holds. The underlying principle has not changed: subagents work best when you only need the final result, not the messy middle. Multi-agent orchestration just gives teams a more formal way to run this pattern at scale.

AI Capabilities and Limitations

Plain-English summary

AI can sound fluent even when it is wrong. The core skill is calibrated trust: know when to rely on it, when to verify, and when not to delegate.

If Claude gives a statistic, date, quote, or source, verify it. Smooth writing is not proof of truth.

Original course notes, revised for v1.1

This playbook gives a Working Mental Model of how generative AI systems operate and why they behave the way they do. It covers the mechanical properties of the machine that human skills (the 4D Framework) must respond to.

Core Principles & Concepts

Generative AI is not uniformly excellent or incompetent. It works on a spectrum (capabilities ↔ limits) of four predictable core properties. Understanding these mechanical properties is the starting point for Calibrated Trust.

AI's Personality: The 2 Stages of Training (Pretraining & Fine-tuning)

  • Pretraining: Reading huge amounts of text to predict the next token, building a Document completer. At this stage, the AI has no concept of helping a user.
  • Fine-tuning: Reflecting human preferences to turn the document completer into an assistant. Human judgment enters here, leaving fingerprints - the assistant's distinctive Sycophancy (people-pleasing), Verbosity (talking too much), and Over-caution.

Next Token Prediction: The Two Sides of Fluency and Hallucination

  • A base language model does not automatically retrieve fresh information. It predicts the next piece of text from patterns it learned. Retrieval, search, or tools can add external information when enabled.
  • On familiar patterns (summary, explanation), it shows powerful ability. But where Specificity matters - names, dates, quotes, statistics - Hallucinations (made-up facts) and Confabulation (filling gaps with fiction) cluster. A fluent tone does not guarantee accuracy.

Knowledge: Vast but Frozen

  • AI's knowledge depends entirely on its training data and is frozen at a specific point in time (Knowledge cutoff).
  • It has deep capability on mainstream topics but suffers from Staleness and Source amnesia for rare, recent, or local subjects.

Working Memory: The Cliff of the Context Window

  • The space the AI is currently paying attention to is the context window. Its size depends on the model and product setup.
  • Unlike other properties that decline gradually, memory can hit a cliff. In newer API settings, oversized requests may return a validation error instead of silently truncating, but the practical lesson is the same: manage context deliberately. Especially "Lost in the middle" - information in the middle of a long document gets ignored.

Steerability: The Gap Between Words and Intent

  • Note: The original document does not include a detailed bullet body for this property - only the heading. Steerability refers to how well the AI follows the spirit of your instructions, not just the literal words.

Practical Implementation Guide

Concrete methods for applying the four machine properties to your work (4D: Delegation, Description, Discernment, Diligence) - to control output quality and prevent errors.

A. Context Optimization Workflow (for Working Memory)

  • Principle: More context does not mean better results. The AI's attention is finite - Curate ruthlessly.
  • Prompt Structuring (a safe pattern): Place the most important instructions or constraints both at the very top and the very bottom of the prompt. Information buried in the middle has a high chance of being ignored.
  • Chunking: When reviewing documents over 50 pages, don't upload all at once - split into logical units and work in multiple passes.
  • Context Reset: If output quality drops during a long conversation (context limit reached), briefly summarize the situation and start fresh in a New Chat.

B. Hallucination Control and Verification Checklist (for Next Token Prediction & Knowledge)

  • Targeted Specificity Verification: If AI output contains names, dates, statistics, quotes, or URLs, make those your top verification priority. The more precise the claim, the more likely Fabrication is hiding inside.
  • External Knowledge Injection: When you need recent information or company-internal information (post-cutoff or non-public), don't rely on the AI's knowledge. Use web search, RAG (Retrieval-Augmented Generation), or paste relevant documents directly into the prompt (Context-as-leverage) to fill the gap.
  • Trigger Uncertainty Signals: Add a constraint in the prompt: "If you're not sure, don't guess - say you don't know or note that there isn't enough information." This blocks confabulation.

C. Prompting for Precise Steering (for Steerability)

  • Provide Format AND Goal Together: To prevent the AI from interpreting instructions too literally, state the underlying purpose.

Anti-pattern: "Make this email shorter." (key content might disappear)

Best Practice: "Make this email shorter. My goal is to keep executives focused all the way through to the key results on page 2."

Strategic Insights & Considerations

Most real-world AI failures aren't about a single property breaking. The Master diagnoses not "What broke?" but "Which two properties collided?"

Diagnosing Property Collisions (When Properties Collide)

  • Hallucinated Citation = [Next Token Prediction] × [Knowledge Limit]: On a niche topic, the AI generates a paper title and author that sound plausible but don't exist. The machine can't tell what it knows from what it invented. (Solution: independent verification or grounding in a real document.)
  • Long-conversation Drift = [Working Memory Limit] × [Steerability]: Strict constraints set early get ignored after twenty messages. Initial context fades, and the AI matches patterns from the most recent instructions only. (Solution: re-supply the core context or start a new session.)

Real-world Anti-patterns to Avoid

  • Polarized Trust (full trust vs. full distrust): Trust in AI is not given or taken away. Identify whether the current task is in the AI's capability area (well-paved road) or limit area (new territory), and adjust your verification accordingly. This is Calibrated trust.
  • Repeating with More Force: When the AI follows instructions literally and misses the intent, repeating "Be more concise!" doesn't close the gap. Re-explain the Goal, not the instruction.
  • Misreading Confidence: The AI's smooth, confident prose only means "next token prediction worked well" - it's not a signal that the content is True.

A Sustainable Mental Model

  • Even as AI model versions advance and context windows grow, the Shape of these four properties doesn't change. AI is still a predictor where fluency runs ahead of accuracy, working in a finite window, following instructions through the gap between words and intent. This mental model holds up through technological change.
Master one-liner

Don't be fooled by AI's fluency - understand the four essential properties of the

machine (prediction, knowledge, memory, steerability) and build calibrated trust."

Non-tech takeaway

This is the safety course: trust by task type, not by tone.
